# Публичное демо на Render и Neon

Используйте ветку `demo/render` с режимом просмотра и отдельный проект Neon. PostgreSQL и таблица сессий создаются с нуля.

## База Neon

1. В Neon Console создайте проект на Free в регионе, близком к будущему сервису Render. В **Connect** выберите новую базу и прямое подключение (Connection pooling выключен).
2. Возьмите выданный Neon URL с `sslmode=require`. Используйте его как `DB_URL` для Laravel. Храните строку только в менеджере секретов или переменных окружения. Для локального заполнения передайте её доверенному процессу через окружение, без вставки значения в командную строку.
3. Из проверенной рабочей копии с установленными зависимостями запустите команды ниже локально с PHP 8.4.1+ и `pdo_pgsql`. Альтернатива — запустить те же команды в собранном образе через `docker run --rm -e DB_URL -e DB_CONNECTION -e APP_ENV -e APP_KEY -e APP_DEBUG -e CACHE_STORE remont-crm:render php artisan …`, заменяя многоточие аргументами команды. Используйте `DB_CONNECTION=pgsql`, `APP_ENV=production`, `APP_DEBUG=false`, `CACHE_STORE=database` и новый `APP_KEY`. Перед записью проверьте в Neon, что выбран нужный новый endpoint и база пуста. Если локальный PHP и Docker недоступны, подготовьте доверенный исполнитель до создания Web Service.

```bash
php artisan migrate --force --no-interaction
php artisan db:seed --class=DatabaseSeeder --force --no-interaction
php artisan migrate:status --no-interaction
```

Сидер запускается один раз на чистой базе и создаёт все четыре аккаунта, роли и связанные демоданные. Будущие миграции выполняйте отдельно перед выкладкой версии, которая их требует. Render Free не предоставляет SSH, Shell, one-off jobs и pre-deploy command для Web Service. Сборка и запуск контейнера обходятся без доступа к Neon на этапе сборки и без запуска миграций или сидера при старте.

## Сервис Render

После отдельного разрешения отправьте проверенную ветку `demo/render` на GitHub. В Render выберите **New → Web Service**, репозиторий проекта, ветку `demo/render`, Runtime **Docker**, Dockerfile `./Dockerfile`, Instance Type **Free**. Оставьте Docker Command пустой, укажите Health Check Path `/up` и выключите Auto-Deploy, если выкладки должны запускаться вручную. Кнопка **Create Web Service** запускает первую сборку и выкладку, поэтому заполните переменные до нажатия.

| Переменная | Значение |
| --- | --- |
| `PUBLIC_DEMO_MODE` | `true` |
| `APP_ENV` | `production` |
| `APP_DEBUG` | `false` |
| `APP_KEY` | Новый секрет из `php artisan key:generate --show`, хранить только в окружении |
| `APP_URL` | Канонический HTTPS-адрес. Если оставить переменную незаданной, Laravel возьмёт системный `RENDER_EXTERNAL_URL`. |
| `DB_CONNECTION` | `pgsql` |
| `DB_URL` | Секрет с прямым TLS-подключением Neon |
| `SESSION_DRIVER` | `database` |
| `SESSION_SECURE_COOKIE` | `true` |
| `CACHE_STORE` | `database` |
| `QUEUE_CONNECTION` | `sync` |
| `MAIL_MAILER` | `log` |

Оставьте `ASSET_URL` пустой. При HTTPS в `APP_URL` Laravel формирует HTTPS-ссылки на Render, где TLS завершается на прокси. Локальный запуск по HTTP сохраняется. Docker запускает встроенный сервер PHP для портфолио-демо из `public/` через Artisan на `0.0.0.0` и порту `PORT`.

## Приёмка и лимиты

- В первой сборке проверьте установку production-зависимостей из lock-файла, наличие `pdo_pgsql`, сборку Vite и запуск на `PORT`.
- Проверьте ответ 200 на `/up`, главную и загрузку CSS и JS по HTTPS. Проверьте перенаправление с `/login` на главную.
- Для каждой из четырёх ролей начните с гостевой сессии, войдите через кнопку, откройте доступную карточку, обновите страницу и выйдите. Серверный запрет записи проверяйте тестами на изолированной базе.
- Render Free засыпает после 15 минут простоя, даёт 750 часов в месяц на рабочую область и использует временную файловую систему. С подключённой оплатой превышение квот исходящего трафика и минут сборки может привести к начислениям. Без способа оплаты сервисы или новые сборки приостанавливаются. Трафик к внешней Neon также учитывается. [Render Free](https://render.com/docs/free)
- Neon Free имеет квоты вычислений, хранения и исходящего трафика. Проверьте актуальные квоты в Neon Console перед созданием базы. При исчерпании квоты доступность может быть ограничена. Платный тариф учитывает фактическое потребление. [Тарифы Neon](https://neon.com/pricing)
